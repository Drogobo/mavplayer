# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

MavPlayer is a native media player (video, music, streams, DVDs, audio CDs) in Rust: its own playback engine built directly on the FFmpeg C libraries via `ffmpeg-sys-next`, and a GPUI interface. License: GPL-3.0-or-later. README.md covers features and usage; HACKING.md covers building every package format and the code tour in more detail.

## Hard constraints

- **Never depend on mpv or VLC.** All playback goes through the in-house engine in `src/engine/`.
- **Papirus icons come from the git submodule** `third_party/papirus-icon-theme` and are compiled in by `build.rs`. Never commit Papirus files to the repo, and never require Papirus to be installed. The desktop's icon theme is preferred at runtime, and Papirus is only the fallback.
- **Bundled shaders must stay GPL-3.0-compatible.** `third_party/shaders/` holds unmodified mpv shaders (Anime4K, ArtCNN, FSRCNNX, RAVU, AMD FSR/CAS, NVIDIA NIS, KrigBilateral) under MIT or LGPL-3.0+. Every file needs its source in `third_party/shaders/README.md` and its license text in `third_party/shaders/LICENSES.txt`, which all packages install as `SHADER-LICENSES.txt`. Never add shaders under non-commercial, GPL-2.0-only or unclear licenses.
- **FFmpeg 9 is required.** Bindings are generated by bindgen against the installed headers, so FFmpeg enums appear as Rust enums (e.g. `ff::SwsFlags::SWS_BILINEAR`, `AVPixelFormat::…`). Older FFmpeg will not compile.
- **`third_party/xattr` is a vendored, patched xattr 0.2.3.** It is applied via `[patch.crates-io]` because the upstream release references `libc::ENOATTR`, which newer libc removed. Keep it.
- **`third_party/blade-graphics` is a vendored, patched blade-graphics 0.7.1** (GPUI's renderer, via `[patch.crates-io]`). It never enables Vulkan ray tracing, which costs 50 MB per process on NVIDIA. Keep it.
- **`third_party/ksni` is a vendored, patched ksni 0.3.7** (also via `[patch.crates-io]`). The patch adds `dbus_name`: the tray item owns a fixed, replaceable bus name, so the tray hand-over (below) doesn't blink. Keep it.
- **No cross-crate LTO in release** (`lto = false`, and `codegen-units = 1` for the mavplayer package). With thin LTO, the global allocator's `__rust_alloc_zeroed` shim (`mem.rs`) gets copied into other crates' modules, and LLVM 23's inliner then crashes in `LazyCallGraph::removeDeadFunctions`. Whether it crashes depends on chance; CachyOS's makepkg `-C target-cpu=native` set it off every time. Fat LTO is safe but takes 7 minutes. Don't turn thin LTO back on.
- **On Linux, `main` ends with `libc::_exit(0)`.** A normal exit runs CUDA's exit handler while `video-dec` threads may still be freeing NVDEC decoders, and that crashed every quit after hardware-decoded playback. Anything that must reach disk has to be written before GPUI's loop ends (settings and resume positions are saved when the window closes).

## Commands

```bash
git submodule update --init --depth 1     # needed once; build.rs panics without Papirus
cargo run -- path/to/video.mkv            # dev build (opt-level 1, deps at 2)
cargo run --release -- -v video.mkv       # -v / MAVPLAYER_DEBUG=1: stderr log incl. time to first frame
cargo test                                # unit tests
cargo test time_roundtrip                 # a single test by name
cargo clippy --locked -- -D warnings      # CI enforces
MAVPLAYER_NO_DVDNAV=1 cargo clippy --locked -- -D warnings   # the build without DVD menus (Windows) must pass too
cargo fmt --check                         # CI enforces (rustfmt.toml: max_width 120)
```

Packaging (details in HACKING.md):
- **Static FFmpeg for portable builds:** `scripts/build-ffmpeg.sh` builds FFmpeg 9 plus dav1d, zimg, libdvdread/dvdnav and nv-codec-headers into `ffmpeg-build/prefix`. Then build with `PKG_CONFIG_PATH=$PWD/ffmpeg-build/prefix/lib/pkgconfig cargo build --release --features static-ffmpeg`.
- **Linux packages:** `scripts/package-linux.sh [deb] [rpm] [appimage]`. Uses cargo-deb, cargo-generate-rpm and linuxdeploy. The deb/rpm metadata lives in `Cargo.toml`.
- **Arch:** `cd packaging/arch && makepkg -s`. This is an in-tree PKGBUILD that builds against the system FFmpeg.
- **Flatpak:** manifest in `packaging/flatpak/`. It needs a `cargo-sources.json` generated from `Cargo.lock`.
- **Windows:** `scripts/package-windows.ps1`. Uses the BtbN FFmpeg shared build plus Inno Setup.
- **macOS:** `scripts/package-macos.sh`. Produces an .app and .dmg. It fails if any non-system dylib is linked.
- **CI:** `.github/workflows/build.yml` builds all of the above. A `v*` tag publishes a release.

## Architecture

### Engine (`src/engine/`, no UI code)

The engine is an ffplay-style threaded pipeline, one set of threads per playback session (`SessionCtx` in `engine/mod.rs`):

- `demux.rs` reads packets and routes them into per-kind `PacketQueue`s. It also handles seeks, track switches, pause, back-pressure and EOF.
- `video.rs`, `audio.rs` and `subs.rs` decode on their own threads. Video and audio frames pass through libavfilter graphs built from the current settings (`filters.rs`).
- `decoder.rs` shares hardware devices across decoders (opening one takes 100–500 ms). `demux::open_input` prewarms one when the file has a video stream; never from `Player::new` or in the tray (a CUDA device is about 100 MB). Devices unused for 30 s are closed (`release_idle_hw`, from the `mem.rs` thread), and a decoder at the end of a file closes its codec after 20 s without a seek (`Decoder::park`/`unpark`). Downloaded frames come from `DownloadPool`. On Linux it tries CUDA before VAAPI when VAAPI would go through NVIDIA's NVDEC wrapper driver (`vaapi_is_nvdec`).
- `present.rs` picks the frame due now against the master clock (`compute_target_delay`), converts it with swscale to BGRA at display size, and hands it to the UI.
- `upscale.rs`: GPU upscalers (Settings → Video → Upscaling). When enlarging, `video.rs` appends FFmpeg's `libplacebo` filter at display size, with the bundled shaders passed as `custom_shader_bin`. It shares one Vulkan device (closed after 30 s unused), caches compiled shaders, waits for the window size to settle, and doesn't run before the UI reports a size. It is optional: if FFmpeg lacks libplacebo, only Bilinear (the GPU drawing the texture) and Nearest (swscale, in `present.rs`) are offered. `scripts/build-ffmpeg.sh` (Linux only, not macOS) and the Flatpak build libplacebo; the static build links it and glslang statically but only `dlopen`s the Vulkan loader.
- The audio output callback consumes samples and **drives the master clock**. Video is the master only when there is no audio.
  - On Linux it is a native PipeWire stream (`audio/pw_out.rs`: proper channel positions, exact delay, "MavPlayer" in mixers). cpal is the fallback when no PipeWire server is running (ALSA), and the backend on Windows and macOS.

Key invariants that span files:

- **Serials.** Every queue item carries a serial, and a seek bumps it. Each stage drops items whose serial doesn't match the queue's current serial. Preserve this when adding stages or queues.
- **Filter-graph rebuilds.** Settings changes reach decoder threads through `Controls` (shared, with generation counters). The decoder threads rebuild their graph when the key changes. There is no explicit "apply" call.
- **Audio startup never blocks video.**
  - The device opens on the audio thread. Meanwhile `SessionCtx::audio_pending` (a token) makes the presenter show the first frame but hold playback.
  - If no device is available, it doesn't open within 3 s, or it stops requesting samples (watchdog), `audio.rs` switches to `null_sink`. This consumes audio in real time so the clock keeps running.
  - A `claimed` flag stops a late device and the fallback from both consuming the buffer.
  - Debug builds honour `MAVPLAYER_TEST_AUDIO_DELAY_MS` to simulate a slow or hung device.
- **Gapless playback.**
  - The UI queues the next item (or the same file, for loops) with `Player::set_next`. Near the end, `preload_next` starts it as a *standby* session: its `update_state`/`emit` are collected in `SessionCtx::standby`, and the presenter and output hold it silent.
  - The audio output (`audio::OutputLink`) outlives sessions. A standby session with the same device/layout queues its feed on it, and `CallbackState::run` switches mid-buffer when the current feed is `drained`, then calls `promote()`. Otherwise the demuxer's `advance()` promotes at EOF.
  - `Player` adopts the promoted session in `adopt()` (from `drain_events` and the `&mut` methods) and shuts the old one down. Output threads are never joined while the output has moved on to another session (`finish_output`).
- **DVDs with menus** (`Dvd { title: 0 }`, when `cfg(has_dvdnav)` and the `dvd_menus` setting are on) go through `nav.rs`: libdvdnav runs the disc's VM and its blocks reach FFmpeg's `mpeg` demuxer through a custom AVIOContext (`av::custom_io_context`/`IoSource`).
  - Playback is split into segments (menu domain, VTS or title). libdvdnav events (still, wait, hop, VTS/title change, stop) end the read with EOF and `play_segment` handles them. Stills and waits *drain* decoders without bumping serials; jumps flush. Each segment has its own outer `FormatCtx` with streams built from the IFO attributes, and components restart per segment.
  - Timestamps become one continuous timeline: an offset per VOBU (from the PCI's `vobu_s_ptm`/`vobu_e_ptm`), looked up by packet `pos`, rebased from `dvdnav_get_current_time` at segment start and after jumps and seeks.
  - Subpictures go through our own `spu.rs` decoder (`SessionCtx::spu_overlay`), not FFmpeg's, so button highlights (libdvdnav's rectangle and palette + the CLUT) can be redrawn when the selection changes.
  - The UI sends `DvdCommand`s via `Player::dvd_command` and reads `PlaybackState::dvd`. While buttons show, the key context is `Player DvdMenu`; its arrow/Enter bindings come from `keymap::apply`.
  - `build.rs` sets `cfg(has_dvdnav)` (static FFmpeg: libavformat's static libs include `-ldvdnav`; otherwise `pkg-config dvdnav`). `MAVPLAYER_NO_DVDNAV=1` turns it off. Windows has no libdvdnav. Anything only nav mode uses must be gated or `cfg_attr(not(has_dvdnav), allow(dead_code))`.
- **DVD titles** (`Dvd { title: n }`, or menus off/unavailable) go through FFmpeg's `dvdvideo` demuxer (title/angle/region options). `disc.rs` probes titles, and the longest title is treated as the main feature.
- **Audio CDs** (`Cd { device, track }`, `cdda://[TRACK][/DEVICE]`, `.cue`/`.bin` images): `cdda.rs` reads the TOC, CD-Text and raw sectors (Linux `CDROM*` ioctls, Windows `IOCTL_CDROM_*`, untested; macOS mounts CDs as AIFF files). `demux.rs` opens them with the `s16le` demuxer through a seekable custom IO. Track 0 means the whole disc; the UI expands it into one playlist entry per track. `disc::read_disc` tells DVDs, CDs and mounted CDs apart for the Open Disc dialog.
- **UI boundary.** The UI only talks to the engine through `engine::Player` (load/seek/pause/volume/select_track/set_config/take_frame/state/drain_events). The engine wakes the UI through the callback passed to `Player::new`.

### UI (`src/ui/`, GPUI 0.2)

All state lives in one view, `PlayerView`. Its `impl` blocks are split by concern:
- `player.rs`: state, engine plumbing (wake loop plus 200 ms `tick`) and action handlers in `register_actions`.
- `render.rs`: rendering.
- `menus.rs`: menu contents.
- `menu.rs`: the popup-menu widget.
- `dialogs.rs`: all modals.
- `actions.rs`: the `actions!` list and the macOS native menu.
- `shell.rs`: what outlives the window: opening it, `Incoming` requests (later launches, the OS, the tray), and the tray hand-over (below).
- `tray.rs`: the tray icon and its Open/Quit menu (`ksni` on Linux, `tray-icon` on Windows and macOS).
- `keymap.rs`: the `COMMANDS` table (every rebindable command, its group and default keys). `keymap::apply` rebuilds GPUI's keymap from it plus `Settings::key_bindings` (the user's overrides, set in Preferences → Keyboard Shortcuts, `dialogs.rs` `shortcuts_pane`), and menus/tooltips read labels via `shortcut_for`/`hint`. While that page records a key, a `cx.intercept_keystrokes` hook in `PlayerView::new` takes the keystroke before any binding fires.

To add a keyboard action:
1. Add it to `actions!`.
2. Add it to `keymap::COMMANDS` with its default keys (`secondary-` means Ctrl, or ⌘ on macOS). Never call `cx.bind_keys` elsewhere: `apply` clears and rebuilds the whole keymap.
3. Handle it in `register_actions`.
4. Optionally add it to a menu with `act()` (it shows the current shortcut).

To add a setting:
1. Add a field to `Settings` in `settings.rs` (it is `#[serde(default)]`).
2. Map it in `Settings::engine_config()` if the engine needs it.
3. Add a control in `dialogs.rs` → `settings_dialog` via `toggle_row`, `choice`, `stepper` or `input_box`.

GPUI gotchas already hit in this codebase:
- **The event loop ends when the last window closes** on Linux (Wayland and X11 `drop_window`) and Windows, and can't be restarted. `show: false` is ignored on Linux. So "Keep running in the system tray" works by hand-over: the closing process spawns `mavplayer --background` (via `flatpak-spawn` in Flatpak, the `$APPIMAGE` file for AppImages) and quits; the new process opens no window, which keeps GPUI's loop alive, takes the instance socket and the tray, and opens a window on request. So the icon never blinks out, the new process (`--handover`) shows its tray icon before anything else. On Linux it takes over the old icon's fixed D-Bus name with `ReplaceExisting` (Plasma drops an item only when its name loses its owner). It then prints a ready line on its piped stdout. The old one keeps its icon past the end of GPUI until then (`shell::finish_handover`, called after `app.run` returns), deletes the instance socket file, closes the new process's stdin (its cue to bind the socket without polling) and exits. Explicit quits go through `shell::quit` so they don't hand over.
- **Nested `deferred()` panics** ("cannot call defer_draw during deferred drawing"). Submenus are therefore siblings inside one deferred layer, anchored to row bounds measured with a `canvas` (`OpenMenu::anchors`).
- **Textures.** Video frames are `RenderImage`s. Replaced textures must go through `window.drop_image` a few frames later (`retired`), because GPUI frees atlas textures immediately.
- **Wayland quirks.**
  - `cx.primary_display()` is always `None`, and `window.display()` is `None` until the surface enters an output. `fit_window` falls back to `cx.displays()`.
  - A resize issued before the compositor's first configure can be lost, so `pending_fit` re-applies it from `tick`.
  - The window icon comes only from a `.desktop` file matching the app ID (`io.github.drogobo.MavPlayer`). For unpackaged runs, `integration::ensure_window_icon()` writes a hidden icon-only entry.
- **Flex children shrink.** Rows inside a height-limited flex column (menus, dialog lists) need `flex_none()`, or they squash instead of scrolling.
- **Scrollbars.** GPUI has none. `widgets::scrollbar(id, &ScrollHandle, theme)` is an absolutely positioned sibling of the scroll area (inside a `relative()` parent). Track the area with `.track_scroll(&handle)`; for a `uniform_list` use `pl_scroll.0.borrow().base_handle`.
- **Bundled SVGs.** Load them as `ImageSource::Resource(Resource::Embedded(..))`. `img("x.svg")` is parsed as a URI.

### Other modules

- `icons.rs`: freedesktop icon lookup in the user's theme (KDE/GTK settings, the Inherits chain, Flatpak `/run/host`), with the bundled Papirus fallback served by the `Assets` AssetSource.
- `integration.rs`: AppImage desktop integration (`--integrate`, `--remove-integration`, first-run prompt).
- `playlist.rs`: CLI/URL/`dvd://`/`cdda://` parsing and M3U/PLS handling.
- `font_prefetch.rs` (Linux): GPUI's cosmic-text runs fontdb's `load_system_fonts()` serially inside `Application::new()`, and on a cold page cache that can take seconds. `main` first runs the same parse on several threads with `MADV_RANDOM` mappings, then joins it before `Application::new()`. Keep its fontdb/fontconfig-parser versions the same as cosmic-text's.
- `mem.rs` (memory): a global allocator that keeps a few freed blocks of 1 MB or more (video frames) for reuse, glibc's mmap threshold fixed at 1 MB, and a thread that trims malloc and closes idle GPU devices each second. Measure memory changes with PSS from `/proc/PID/smaps_rollup`, and run the binary from a disk path: binaries on tmpfs (`/tmp`) show their code as private dirty.
- `instance.rs`: hands files from a new launch to the open window (Unix socket, or loopback TCP + token on Windows), per the `when_running` setting.
- `ui/media_keys.rs`: media keys and now-playing info via souvlaki (MPRIS over zbus, SMTC, Now Playing). The first window owns `org.mpris.MediaPlayer2.mavplayer`, later ones `…mavplayer.instance<pid>`.

Keep `integration::MIME_TYPES` and the static `packaging/linux/*.desktop` MimeType list identical.

## Testing the GUI

Don't launch test windows on the user's live desktop. On KDE/Wayland, run inside an isolated, invisible compositor and screenshot it:

```bash
dbus-run-session -- bash -c '
  kwin_wayland --virtual --no-lockscreen --width 1280 --height 800 --socket mavtest &
  sleep 2
  WAYLAND_DISPLAY=mavtest MAVPLAYER_CONFIG_DIR=/tmp/mp-cfg cargo run -- video.mkv &
  sleep 4
  WAYLAND_DISPLAY=mavtest spectacle -b -n -f -o shot.png'
```

Notes on this setup:
- To isolate audio and data too, point `XDG_RUNTIME_DIR`, `XDG_DATA_HOME`, `XDG_CACHE_HOME` and `XDG_CONFIG_HOME` at a scratch folder. Playback is then silent through the null sink.
- Keep the socket path under 108 bytes.
- `--no-lockscreen` matters: without it the nested KWin follows the real session's lock state, and every screenshot shows a lock screen while the desktop is locked.
- The nested session has no tray host. To test the tray, run a stand-in `org.kde.StatusNotifierWatcher` on the isolated bus (a few lines of Python with `gi.repository.Gio`), then drive the item with `gdbus call` on its bus name (`io.github.drogobo.MavPlayer.Tray`, plus `.c<hash>` under `MAVPLAYER_CONFIG_DIR`) (`org.kde.StatusNotifierItem.Activate`, `com.canonical.dbusmenu.GetLayout -- 0 -1 '@as []'` and `Event`).
- `MAVPLAYER_CONFIG_DIR` gives a throwaway `settings.json`. For example, `{"muted":true}` keeps a run quiet.
